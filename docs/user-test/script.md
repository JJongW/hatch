# 진행 대본

과제는 **목표만** 말한다. 버튼 이름이나 위치는 알려 주지 않는다. 참가자가 묻으면 "어디일 것 같으세요?"로 되묻고, 2분 넘게 막히면 힌트를 주고 기록지에 "힌트"로 적는다.

## 0. 시작 (5분)

> 오늘 보는 건 참가자님이 아니라 이 서비스예요. 막히면 서비스가 잘못 만든 거니 편하게 해 주세요.
> 생각나는 걸 소리 내어 말해 주시면 큰 도움이 돼요. "이게 뭐지?", "여기 누르면 될 것 같은데" 같은 거요.
> 문서를 만드는 데 한 번에 20초에서 1분쯤 걸려요. 기다리는 동안 제가 몇 가지 여쭤볼게요.
> 화면 녹화를 해도 될까요? 이름과 얼굴은 남기지 않아요.

사전 질문 (기록지 0번):
1. 요즘 기획 문서(기획안, PRD 등)를 쓸 때 AI를 어떻게 쓰세요?
2. 아이디어는 어디에 모아 두세요?

## 과제 1. 아이디어 남기기 (3분)

> 가져오신 아이디어를 Hatch에 남겨 주세요. 나중에 찾기 쉽게 묶어 두고 싶으면 그렇게 해 주세요.

볼 것: 폴더 칸을 알아채는지, 저장 뒤 어디로 가야 하는지 아는지

예시 아이디어 (가져온 게 없을 때): "동네 헬스장 PT 예약을 카톡 대신 앱으로. 트레이너가 카톡으로 시간을 하나씩 잡고, 회원은 빈 시간을 모른다."

## 과제 2. 맥락 적기 (3분)

> 이 아이디어의 대상 고객과 목표를 Hatch에 알려 주세요. 앞으로 만드는 문서마다 반영되게요.

볼 것: 상세 화면에서 맥락 칸을 찾는지, 네 칸(목표 고객, 목표 지표, 제약, 이미 아는 사실)을 이해하는지

## 과제 3. 기획안 만들고 지금 할 일 찾기 (5분) → H1

> 기획안을 만들어 주세요.

(생성 중) "기다리는 이 시간이 어떠세요?" 

> 다 됐네요. **이 아이디어에서 지금 내려야 할 결정이 뭔가요?** 찾으시면 말로 알려 주세요.

볼 것: 답을 말하기까지 걸린 시간(초), 요약 판을 봤는지 문서 본문을 뒤졌는지

## 과제 4. 모르는 것을 질문으로 (8분) → H2

> 문서에 아직 확인이 안 된 부분이 있어요. 그걸 고객이나 동료에게 물어볼 질문으로 정리해 주세요.
> 그중 지금 답할 수 있는 것 하나에 답해 주세요.

볼 것: 질문 수를 보고 한 말, 끝까지 훑는지, 답한 내용이 "결정"으로 남은 걸 알아채는지

## 과제 5. 결정 반영하고 영향 보기 (6분) → H3, H4

> 방금 답한 내용이 기획안에 들어가게 해 주세요.
> (다 되면) 무엇이 달라졌나요? 다른 문서에도 영향이 있을까요?

로드맵과 PRD는 과제 3이 끝난 직후 진행자가 만들어 둔다 (약 1분). 그동안 사전 질문을 이어서 묻는다. 생성은 한 번에 하나만 돌아서, 참가자 과제 중에 진행자가 만들면 참가자 버튼이 막힌다.

볼 것: 바뀐 곳을 스스로 짚는지(H3), 로드맵에 붙은 표시를 보는지, PRD도 낡았다고 생각하는지(H4)

## 과제 6. PRD 반론 듣고 고치기 (10분) → H5

> 이 PRD를 개발, 디자인, 마케팅, CS 관점에서 검토받고, 받은 반론 하나를 골라 PRD에 반영해 주세요.

볼 것: PO 도구로 가는 길을 찾는지, 1분 30초 대기 중 행동(H5), 반론을 PRD 편집으로 옮기는지

## 과제 7. (시간 남으면) 고객 의견 정리 (5분)

> 고객 의견 몇 줄을 붙여 넣고, 무엇부터 해결할지 순서를 정해 주세요.

붙여 넣을 의견 예시:
```
트레이너한테 카톡하면 답이 늦어서 그냥 안 가게 돼요
빈 시간이 언제인지 한눈에 보고 싶어요
예약 바꾸려면 또 연락해야 해서 귀찮아요
전날 알림이 오면 좋겠어요
```

볼 것: AI가 매긴 점수를 그대로 믿는지, 사람이 순서를 바꾸는지

## 과제 8. 채팅으로 같은 일 하기 (10분) → H7

순서 효과를 줄이려고 **홀수 참가자(P1 · P3 · P5)는 과제 1 앞에서, 짝수 참가자는 과제 7 뒤에서** 한다.
참가자가 평소 쓰는 AI 채팅(Claude, ChatGPT 등)을 쓰게 한다. 같은 아이디어, 같은 맥락을 쓴다.

> 평소 쓰시는 AI 채팅으로 이 아이디어의 기획안, 개발 로드맵, PRD를 만들어 주세요. 평소 하시는 방식 그대로요.
> (다 되면) 기획안에서 "결제는 현장 결제만 지원한다"로 바뀌었어요. 다른 문서 중 어디를 고쳐야 하나요?

볼 것: PRD까지 걸린 시간, 앞 문서를 붙여 넣는지, 영향 질문에 답하기까지 걸린 시간과 맞혔는지(로드맵 · PRD 둘 다)
끝나면 세 문서를 참가자 동의를 받아 `.md`로 저장한다 (이름 · 회사 정보는 지운다). 단정 수치는 `tools/count-claims.mjs`로 센다

## 마무리 (5분)

사후 질문 (기록지 마지막 칸):
1. 쓰기 쉬웠나요? (1~5)
2. 만든 문서를 믿고 팀에 공유할 수 있나요? (1~5)
3. 다음 주에 실제 일에 다시 쓸 것 같나요? (1~5)
4. 가장 헷갈렸던 순간 하나는?
5. **Claude 채팅 대신 Hatch를 쓸 이유가 있다면 한 문장으로?** → H6
6. 이게 있으면 쓰겠다 싶은 것 하나는?

> 오늘 넣은 아이디어는 가져가실 수 있어요. 남길지 지울지 알려 주세요.
