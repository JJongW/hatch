## 3. 참가자

- 3~5명. 지금 PO, PM이거나 최근 1년 안에 기획 문서를 써 본 사람
- 섞어서 뽑는다: 주니어와 시니어, 서비스 기획과 사업 쪽
- 미리 부탁할 것: "지금 고민 중이거나 예전에 접은 서비스 아이디어 한 줄"을 가져오기. **회사 내부 정보나 개인정보는 빼고** 가져오게 한다. 없으면 대본의 예시 아이디어를 쓴다

## 4. 준비

- **환경:** 진행자의 맥에서 실행한다. 데모 사이트는 생성이 안 되므로 쓰지 않는다
- **데이터:** 참가자 데이터가 `~/Hatch`에 섞이지 않게 참가자마다 빈 폴더를 쓴다

```bash
mkdir -p ~/HatchTest/p1 && HATCH_DATA_DIR=~/HatchTest/p1 npm run dev
```

- 시작 전 확인: `claude -p "안녕"`이 답하는지, 아이디어 하나로 기획안이 만들어지는지
- 화면 녹화는 참가자 동의를 받은 경우에만. 얼굴과 이름은 기록에 남기지 않고 P1~P5로 부른다
- 한 사람당 45~60분. 생성 대기가 있어 과제 사이에 질문을 끼워 넣는다

## 5. 재는 것

- 과제마다: 혼자 성공 / 힌트 뒤 성공 / 실패, 걸린 시간, 막힌 곳
- 사후 점수 1~5: 쓰기 쉬움, 결과를 믿을 수 있음, 다음 주에도 쓸 의향
- 한 문장: "Claude 채팅 대신 Hatch를 쓸 이유"

## 6. 끝난 뒤

- 참가자 폴더(`~/HatchTest/pN`)는 참가자에게 원하면 넘기고, 지울지는 참가자에게 묻는다
