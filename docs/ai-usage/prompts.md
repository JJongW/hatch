## 2. 지시가 어떻게 바뀌었나
- **처음엔 길게, 나중엔 짧게.** 서비스 정의 · 작업 체계는 문단으로 썼고, 규칙이 CLAUDE.md · spec에 들어간 뒤로는 "ㄱㄱ" · "머지"만으로 충분했다. 맥락을 프롬프트가 아니라 파일에 둔 효과
- **바로잡은 지시 4번.** 과제 순서 따라가기 → 서비스부터 / Claude API → 로컬 / CI 추가 → 빼기 / 영어 답 → 한국어. 모두 AI의 기본 가정을 내가 끊은 것이다. 바로잡은 내용은 다음부터 반복하지 않게 CLAUDE.md나 메모리에 남겼다
- **결정은 객관식으로.** 설계 단계마다 AI가 2~4개 선택지와 추천을 주고 나는 골랐다. 자유 서술보다 빠르고, 고른 답이 그대로 spec에 남는다

## 3. AI가 다른 AI에게 준 프롬프트 (서브에이전트 · 세션 brief)
병렬 작업은 메인 AI가 쓴 brief로 시작한다. C-3 세션 brief의 구성:
1. 할 일 한 줄 + 끝 조건("PR까지, 머지 금지")
2. 먼저 읽을 파일 (루트 · 폴더 CLAUDE.md · `new-po-tool` 스킬 · spec 해당 절 · 참고 도구)
3. 만들 것 — spec 숫자 그대로 (예: "p1 10% · 효과 10% → 변형당 14,751명")
4. 규칙 — 공통 틀 파일 수정 금지, 등록 줄은 한 줄씩, 포트 3102, 실제 claude 한 번
5. 검증 명령 · 커밋 형식 · PR 제목 · 라벨

brief는 맥락 전체가 아니라 **읽을 파일 목록**을 준다. 세션 하나가 받는 지시는 약 60줄이다.

## 4. 앱 안 프롬프트 구조
모든 프롬프트 문자열은 `src/lib/prompts/`에만 둔다 (코드에 흩어 두지 않는다).

```
공통 규칙(CHAIN_RULES / TOOL_RULES) + 단계 · 도구 프롬프트 + ## 입력 + (### 입력 문서) + 도구 입력
```
- 공통 규칙 (`context.ts`): "입력에 없는 사실은 지어내지 말고 `[확인 필요: ○○]`" · "평균 · 합계 · 개수 · 순위 계산은 하지 않는다" · "마크다운 문법은 쓰지 않는다 (형식은 코드가 만든다)"
- 출력은 JSON 스키마(zod → JSON Schema)로 받는다. 계산 · 서식은 코드가 한다 ([결정](../decisions/2026-10-28_AI는-판단-코드는-계산.md))

| 파일 | 쓰임 |
| --- | --- |
| `chain/plan.ts` · `roadmap.ts` · `prd.ts` · `spec.ts` · `dev-prompt.ts` · `design-prompt.ts` | 문서 체인 6단계 |
| `tools/prd-review.ts` · `voc.ts` · `metrics.ts` · `negotiation.ts` | PO 도구 4종 |
