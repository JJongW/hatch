# AI 실수를 잡아 고친 사례

"어떻게 잡았나"가 핵심이다. 잡은 장치는 네 가지: **실제 실행** · **리뷰 에이전트** · **브라우저 확인** · **사람 승인 규칙**.

| # | 실수 | 어떻게 잡았나 | 어떻게 고쳤나 | 다시 안 생기게 |
| --- | --- | --- | --- | --- |
| 1 | 과제 문서 STEP을 그대로 따라가며 바로 만들기 시작 | 내가 읽고 끊음 ("엥 아니야. 일단 PO의 입장에서…") | 무엇을 만들지부터 다시 | 단계마다 설계(spec) → 내 확정 → plan 순서를 규칙으로 |
| 2 | "Claude 워크플로우"를 Claude API 연동으로 이해 | 내가 바로잡음 ("Claude API를 이야기한게 아니라 내부 로컬…") | 로컬 `claude -p` 실행기로 설계 | [결정 기록](../decisions/2026-10-28_로컬-claude-생성.md) |
| 3 | 사용자 스토리에 "직장인로서" (조사 오류) | **실제 실행** — B-2에서 실제 claude로 6문서를 만들어 읽다가 발견 | 받침을 보고 "로서/으로서"를 코드가 고름 + 테스트 | 문장 조립 중 조사가 붙는 곳은 코드로 |
| 4 | 로드맵 마일스톤 이름에 "MVP"가 두 번 들어감 (코드가 붙인 것 + AI가 쓴 것) | **실제 실행** | 프롬프트에 "MVP · 번호는 코드가 붙이니 쓰지 않는다" → 다시 만들어 확인 | [프롬프트 변경 기록](prompts.md#5-앱-안-프롬프트-변경-기록) |
| 5 | 이름이 형식 밖인 폴더 하나로 아이디어 목록 화면 전체가 깨짐 | **리뷰 에이전트** (`hatch-reviewer` 🔴) | 깨진 폴더는 건너뛰고 개수만 표시 + 테스트 | storage CLAUDE.md 규칙 "깨진 파일은 건너뛰고 개수만" |
| 6 | 폼 제출 뒤 Montage 선택 상자가 첫 값으로 되돌아감 (React 19 폼 리셋) | **구현 중 확인** — 구현 에이전트가 발견하고 리뷰가 바꾼 방식을 승인 | `<form action>` 대신 제출 이벤트 + FormData | `new-po-tool` 스킬 "교훈"에 기록 → C-2~4가 같은 실수 안 함 |
| 7 | 입력 검사 오류가 영어(zod 기본 메시지)로 화면에 나옴 | **리뷰 에이전트** (작업 리뷰) | 도구마다 한국어 메시지 | 스킬 · 병렬 세션 brief에 "한국어 메시지 필수" |
| 8 | 다른 기기 주소를 주소창에서 그대로 복사하면 버튼이 막힘 (`https://…:443`) | **리뷰 에이전트** | 스킴 · 포트 · 경로를 떼고 비교 | README에 넣는 값 예시 |
| 9 | 공통 틀에 PRD 리뷰 전용 문구("위원회가 읽는 중")가 박혀 있고, spec의 "VOC는 문서 없이도"를 틀이 못 함 | **브랜치 전체 최종 리뷰** (Opus) — Important 6건 | 도구별 문구 · `sourceOptional` · `validate` 훅을 틀에 추가 | 병렬 시작 **전에** 틀을 고침. 병렬 세션은 틀을 못 건드리게 해서, 늦게 알았으면 세 도구가 각자 우회했을 것 |
| 10 | 병렬 세션 3개가 같은 폴더를 공유하게 시작됨 (앱이 worktree를 못 만듦) | 도구 결과 메시지를 읽고 메인 AI가 발견 | 각 세션이 첫 단계로 자기 git worktree를 만들게 지시. 공유 폴더가 main 그대로인지 확인 | — |
| 11 | 병렬 PR 충돌을 rebase로 풀었는데, 올리려면 force push 필요 | **사람 승인 규칙** — force push는 내 승인 대상 | rebase를 버리고 main을 merge해 일반 push. 다시 검증 후 머지 | 전역 CLAUDE.md "force push는 멈춰서 승인" |
| 12 | C-2 세션이 저장소 **안**(`.claude/worktrees/`)에 작업 폴더를 만들어, main lint가 그 안 빌드 파일까지 검사 → 오류 1만여 개 | 머지 후 main 검증 | 원인 확인 → 작업 폴더 정리 후 lint 0 · 테스트 139개 통과 | 병렬 brief에 작업 폴더 위치를 저장소 밖(`hatch-wt/`)으로 지정 |
| 13 | "제목만 HS산토끼체로"를 페이지 제목(h1) 전체로 이해해 모든 화면 제목에 적용 | 내가 바로잡음 ("제목이라는게 우리 사이트 'Hatch', '해치'만") | 로고에만 적용, 페이지 제목은 본문 글꼴로 되돌림 | 뜻이 둘로 읽히는 말(제목 · 화면)은 적용 범위를 한 줄로 되묻거나, 적용한 곳을 바로 알린다 |
| 14 | 로고 모션에서 "해치"를 애니메이션 코드가 숨기게만 해 둬서, 페이지가 준비되기 전엔 두 이름이 겹쳐 보임 | **브라우저 확인** — 배포 주소에서 로딩 직후 상태를 읽어 발견 | 처음부터 "해치"를 투명하게 그림 | 애니메이션의 시작 상태는 코드가 아니라 화면 그 자체에 둔다 |
| 15 | 다음 행동 문구를 "${문서 이름}예요"처럼 만들어 "기획안예요" · "PRD이"가 나옴 | **브라우저 확인** — 데모 샘플 3개를 열어 문구를 읽고 발견 | 문서 이름 뒤에 조사가 붙지 않는 문장으로 바꿈 | 이름이 바뀌어 들어가는 자리엔 조사를 붙이지 않는다 |
| 16 | 탭 이름 안에 div를 넣어, 라이브러리가 감싼 p 안에 div가 들어가 화면 복원 오류 | **dev 콘솔 확인** — 일반 모드에서 수정 흐름을 누르며 발견 (리뷰 · 빌드는 통과) | 탭 안 요소를 모두 span으로 | UI 컴포넌트에 넣는 자식은 그 컴포넌트가 감싸는 태그를 보고 고른다 |

## 남겨 둔 것 (알고도 안 고친 것)
리뷰가 지적했지만 이유를 적고 남긴 것도 기록한다. 예:
- 같은 초에 같은 도구를 두 번 저장하면 id가 겹칠 수 있음(1/65536) — 혼자 쓰는 로컬 앱, 겹치면 덮어쓰지 않고 오류로 보인다
- 영문 약어 조사("PM로서") — 보기 문제
- "문서 없이" 결과가 붙여넣기 결과와 같은 폴더에 쌓임 — 별도 이슈로 고치는 중
