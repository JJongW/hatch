# "완료" 대신 "생성됨", 앞 문서가 없어도 막지 않는다

**날짜**: 2026-11-03
**관련 파일**: chain-progress.ts, doc-tabs.tsx, idea-card.tsx, to-card.ts, storage/ideas.ts, summary/questions.ts, questions-panel.tsx, storage/doc-inputs.ts, chain/generate.ts, doc-card.tsx, tools/_frame/tool-frame.tsx, try-flow.tsx

## What — 무엇이 달라졌나
- 문서 수 표시가 "7개 모두 완료" → "7개 모두 생성됨", 목록 카드 "7/7 생성됨", 탭 상태 "생성됨"
- 목록 카드에 실제 데이터가 있을 때만 `근거 N` · `결정 N`(정함만) · `PRD 리뷰함` 배지. 0이면 배지가 없다
- 확인 질문 탭: "먼저 볼 것 5개"와 그 기준 문구(팀이 정할 것 먼저, 그다음 [확인 필요]가 걸린 곳이 많은 순), 나머지는 "모두 보기 (나머지 N개)"
- 앞 문서가 없어도 만들 수 있다: "권장 순서는 ○○ 먼저예요. 아직 없는 문서: ○○." + `지금 자료로 만들기` → 빠진 문서와 대신 쓰는 자료를 보여 주는 확인 → 가장 가까운 있는 앞 문서(없으면 아이디어)로 생성. 만든 문서에 "○○ 없이 ○○으로 만들었어요", 빠졌던 문서가 생기면 "빠졌던 ○○이 생겼어요"
- 도구: 고른 아이디어에 받는 문서가 없으면 이유 + `붙여넣기로 계속`. 체험 PRD 리뷰는 `예시 PRD로 계속` (예시라고 밝힘)

## Why — 왜 필요했나
사용자 요청(2026-11-03): 생성됐다고 준비가 끝난 것이 아니다 → "완료" 대신 "생성됨"; 검토됨 · 근거 · 결정은 실제 데이터로만; 점수를 지어내지 말고 미해결 상위부터; 권장 순서는 두되 필요 데이터가 없을 때만 이유와 해결 방법과 함께 막는다.

## 판단 근거
- 먼저 볼 순서는 점수를 새로 만들지 않고 이미 있는 두 값(질문 종류, [확인 필요] 곳 수)만 쓴다. 기준을 화면에 적어 왜 이 순서인지 보이게 했다
- "먼저 볼 것"에 나온 질문은 묶음에서 빼 같은 질문이 두 번 나오지 않는다. 남은 질문 수(현황 카드)는 openTotal로 그대로 센다
- 막지 않기의 입력 계산은 순수 함수(`doc-inputs.ts`) 하나를 화면 · 생성 · 체험이 같이 쓴다. 실제로 쓴 입력은 머리말 `inputs`에 남아, 화면 문구와 바뀜 알림이 저장된 사실에서 나온다
- 아이디어는 항상 있으므로 문서 생성을 막는 경우는 없다 ("준비 중" 단계만 막힘)
- 대신 만들 때 프롬프트에 한 줄을 더해 빠진 문서 내용을 짐작하지 않게 했다 (`prompts/context.ts` missingNote)
- 공통 틀(`_frame/tool-frame.tsx`) 변경은 안내 한 줄 + 버튼 하나뿐이라 도구 PR이 아닌 이 UX PR에 넣었다
