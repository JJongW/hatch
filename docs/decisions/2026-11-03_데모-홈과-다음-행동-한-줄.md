# 데모 첫 화면은 체험이 주 행동, 다음 할 일은 한 값에서

**날짜**: 2026-11-03
**관련 파일**: page.tsx, _components/demo-home.tsx, _components/side-nav.tsx, _components/app-shell.tsx, summary/index.ts, ideas/[id]/next-band.tsx, ideas/[id]/context-panel.tsx, try/flow.ts, try/try-flow.tsx, tools/voc/compute.ts, tools/voc/input-lines.tsx, try/load.ts

## What — 무엇이 달라졌나
- 공개 데모 `/`: 저장 폼 대신 `흐름 체험하기`(주) · `완성된 예시 보기`(보조) + 예시 아이디어 목록. 읽기 전용 안내는 모든 화면 위 데모 띠가 한다. 네비 첫 항목 이름은 데모에서만 "시작". 로컬은 그대로
- VOC 결과에 분석한 입력 원문(`lines`)을 같이 남기고, 결과 아래 접힌 `분석에 사용한 VOC 보기 (N줄)`. 원문이 없는 예전 결과는 "이 결과에는 입력 원문이 저장되지 않았어요"
- 체험 VOC 입력 칸: 결과 건수(24)와 채운 줄 수(15)가 다르면 그 이유를 결과 파일의 수로 밝힌다
- 상세 "다음 할 일"에 `그다음: …` 한 줄. 근거 때문에 바뀐 문서는 버튼이 `근거를 보고 ○○ 검토하기`
- 체험: `tryNext(state)` 하나가 과제 목록의 "지금", "다음 할 일", "그다음", 도구 화면의 "지금 과제" 버튼을 정한다 (전에는 과제 목록과 다음 할 일이 다른 단계를 가리킬 수 있었다). 맥락 적기 과제면 다음 할 일 버튼이 맥락 폼을 연다

## Why — 왜 필요했나
사용자 요청(2026-11-03): 데모 첫 화면의 주 행동은 흐름 체험, 예시는 보조, 읽기 전용이 보이게; VOC 샘플의 입력과 결과 수가 맞지 않으면 지어내지 말고 밝히기; 위 과제 · 상세 다음 할 일 · 도구 버튼이 같은 목표와 주 행동 하나를 가리키기.

## 판단 근거
- 데모 샘플 VOC를 실제 claude로 다시 돌려 입력과 결과를 맞추는 일은 하지 않았다 (실제 생성은 사용자 몫). 대신 가진 수만으로 차이를 말한다
- `lines`는 선택 칸이라 예전 결과 파일은 변환 없이 읽힌다 (저장 형식 판 올림 없음)
- 데모 제한은 이 공개 사이트만의 것이라 로컬 화면은 바꾸지 않았다
- 네비는 `DemoProvider` 밖이라 컨텍스트 대신 prop으로 데모 여부를 넘겼다 (Suspense fallback과 같은 값이어야 hydration이 맞는다)
- 운영 빌드의 React #418 · `$RS parentNode` 콘솔 오류는 이 변경 전 빌드(feat/127)에서도 같은 데모 화면에 난다. 이 PR 범위 밖, 따로 볼 것

## 이어서 더한 것 (같은 PR)
- 데모 도구 화면: 입력 칸이 지금 보는 결과의 입력을 읽기 전용으로 보인다 (지표 = 저장된 세 값, VOC = 저장된 원문 또는 "저장되지 않았어요", 입력 문서 = 결과가 받은 문서)
- 새 판 비교: 지금 판 뒤 ~ 새 판 전에 적은 결정 · 근거를 "새 판에 들어간, 새로 생기거나 고친 것"으로. 새 판 뒤에 바뀐 입력은 "적용해도 이 변화는 들어 있지 않아요" 경고 (새 판도 문서와 같은 규칙으로 바뀜을 계산, 머리말 inputs 없는 예전 초안은 경고 없음)
- 맥락 폼을 열면 첫 칸으로 포커스 · 스크롤. 다음 할 일 문구는 순수 파일(`next-step.ts`)로 옮겨 테스트
- 생성 성공 경로 테스트: 가짜 claude 로드맵 모드로 "기획안 없이 아이디어로 만듦 → 기획안이 생기면 원인 → 다시 만든 새 판은 최신"

## 안 한 것 · 알려진 대가
- 데모 샘플 VOC 다시 실행(15줄로 새 결과)은 안 함 (실제 생성이라 사용자 몫). spec §5의 이 부분은 남은 일
- VOC 결과에 붙여넣은 원문 전체가 로컬 결과 파일에 남는다 (전엔 주제별 대표 3줄만). 공유 사본에는 도구 결과가 안 나간다. 최대 30,000자라 `data`가 수십 KB가 될 수 있다 → `_frame/load.ts`의 "data가 수십 KB" 신호에 닿으면 원문을 따로 읽게 옮긴다. 고객 이름 · 연락처는 붙여넣기 전에 지우라는 안내가 필요해지면 입력 칸 설명에 넣는다
- 체험에서 기획안을 다시 만든 뒤 PRD의 "바뀜"보다 과제 순서(PRD 리뷰)가 먼저 나온다. 설문 H4 응답에 영향이 있을 수 있다
- 새 판 시각은 claude 응답을 저장할 때 찍힌다. 생성 도중 다른 탭에서 적은 결정은 "새 판에 들어간" 목록과 "새 판 뒤에 바뀜" 경고에 함께 보일 수 있다 (드묾, 생성 시작 시각을 남기면 풀림)
