# macOS가 아니어도 설치하고 실행한다

**날짜**: 2026-11-03
**관련 파일**: README.md, .env.example, start-guide.tsx, run.ts, paths.ts, .gitattributes, package.json

## What — 무엇이 달라졌나
README와 "내 환경에서 사용하기" 화면의 준비물이 macOS 하나에서 macOS, Linux, Windows로 바뀐다. Windows에서 npm으로 깐 Claude Code를 앱이 못 찾으면 `.env.local`의 `HATCH_CLAUDE_BIN`에 경로를 넣으라고 화면이 알려 준다. Windows식 `~\Hatch` 경로도 홈 폴더로 읽는다.

## Why — 왜 필요했나
평가표의 재현 항목은 다른 사람이 자기 컴퓨터에서 띄워 보는 것이다. 맥에서만 된다고 적혀 있으면 Windows를 쓰는 심사자는 시작도 못 한다. 코드를 보니 맥 전용 명령은 없었고, 막히는 곳은 안내 문구와 Windows의 실행 파일 찾기뿐이었다.

## 판단 근거
- `claude.cmd`를 셸로 띄우면 JSON 스키마 인자의 따옴표 처리가 cmd.exe에서 깨질 수 있다. 셸을 쓰지 않고 `.js` 경로를 node로 실행하는 길만 열었다
- 저장소 파일은 LF로 고정했다(.gitattributes). Windows Git이 md를 CRLF로 바꾸면 줄 단위 파싱이 어긋날 수 있다
- Linux와 Windows에서는 아직 실제로 실행해 보지 않았다. 맥에서 확인한 것은 검증 명령과 테스트다
- 갈아탈 신호: Windows 사용자가 실행 파일 문제를 두 번 넘게 겪으면 `claude.cmd`를 직접 찾아 주는 코드를 넣는다
