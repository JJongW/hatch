# 화면 색을 Hatch 팔레트로 바꾸고, 승인된 대비 조합만 쓴다

**날짜**: 2026-11-02
**관련 파일**: theme.css, contrast.test.ts, tokens.ts, montage-ui 스킬

## What — 무엇이 달라졌나
화면 바탕이 웜화이트, 넓은 화면 바깥 띠와 입력칸이 라일락, 본문이 잉크, 보조 글이 슬레이트가 된다. Montage 파란 버튼은 코발트가 된다.
흐린(반투명) 회색 글자와 반투명 선이 사라지고, 모든 글자와 경계가 불투명한 팔레트 색이다. 오류, 저장됨, 주의 글자는 따로 색을 쓰지 않고 본문색과 문구로 알린다.
다크 값도 같이 정해 두었지만, 다크 모드를 켜는 것은 #97에서 한다.

## Why — 왜 필요했나
Montage 기본 색은 원티드 브랜드 색이라 Hatch만의 인상이 없었다. 기본 보조 글자는 88%, 61% 투명도라 배경이 바뀌면 대비가 같이 흔들리고, 빨강, 초록, 주황 상태색은 흰 배경 위에서 WCAG AA(4.5:1)를 못 넘었다.

## 판단 근거
- Montage는 테마 객체를 갈아 끼울 수 없고 모든 색이 CSS 변수라, 변수를 덮어쓰는 것이 컴포넌트를 건드리지 않는 유일한 길이다. hex는 `theme.css` 한 곳에만 둔다
- 대비 수치는 사람이 표로 관리하면 틀어지기 쉬워, `theme.css` 값으로 테스트가 다시 계산한다 (AI는 판단, 코드는 계산)
- 상태색을 새로 만들지 않았다. "제공한 색 그대로"가 조건이었고, 상태는 이미 문구, 기호(▲▼), 아이콘으로 함께 전하고 있었다. 숫자만 색이 바뀌던 VOC 줄 수에는 "200줄을 넘었어요"를 붙였다
- 주 행동 오렌지와 강조 옐로는 Montage에 자리가 없어 `hatchColor` 상수로만 쓰게 규칙을 넓혔다. 적용은 #96
