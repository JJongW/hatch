# 구조화 설계 — 폴더 묶음 · 저장 정리 (2026-10-29)

사용자 요청: "아이디어별로 나뉘어지다보니 구조화나 폴더화를 잘해야할 거같아" → "저장 폴더 정리, 아이디어별 폴더 정리, 화면에서의 정리 다 해야해".
지금 아이디어는 `ideas/<날짜-id>/` 폴더가 나란히 있고, 모음 화면은 날짜순 한 줄 목록이다. 아이디어가 늘면 주제별로 찾기 어렵고, 파인더에서는 폴더 이름만으로 무슨 아이디어인지 모른다. 한 아이디어 폴더 안에도 파일이 11개(+ #49 이후 12개) 섞인다.

## 1. 결정 (2026-10-29 사용자 확인)
- "아이디어별 폴더 정리" = 아이디어를 **폴더(묶음)로 묶기**. 아이디어 하나는 **폴더 하나에만** 들어가고, 화면에선 **칩**으로 보인다
- 디스크에는 **idea.md 머리말에 폴더 이름만** 적는다. 아이디어 폴더는 옮기지 않는다 (링크 · 도구 결과 · #49가 안 깨지게)
- "저장 폴더 정리" = ① 폴더 이름(`20261028-1441-n9rp`)만으론 뭔지 모름 → **자동 목록 파일** ② 아이디어 안 파일이 많음 → **생성 문서를 `docs/` 하위 폴더로**
- 화면 문구에 가운데 점(·)을 쓰지 않는다 (#52)
- PR 2개: ① 폴더 묶음 · 화면 (#54) ② 저장 정리 (#55) (각 400줄 / 15파일 안)

## 2. 폴더 묶음 — 저장 (PR ①)
- `Idea`에 `folder: string` (빈 문자열 = 미분류). idea.md 머리말 `folder: 퇴근 후 취미`
- `IDEA_FILE_VERSION` 2 → 3. 2판 이하는 `folder: ''`로 읽는다 (파일은 다음 저장 때 3판이 된다)
- 폴더 이름 규칙 (`cleanFolder`): 앞뒤 공백 정리 · 안쪽 연속 공백 하나로 · 최대 30자 (넘으면 `StorageError('폴더 이름은 30자까지예요.')`) · `미분류`는 빈 값으로 본다 (예약어)
- 폴더 목록은 따로 저장하지 않는다. `listIdeas` 결과에서 모은다 → 마지막 아이디어가 빠지면 폴더도 사라진다
- `createIdea` · `updateIdea` 입력에 `folder?: string` 추가. Server Action은 폼의 `folder` 칸을 넘긴다

## 3. 폴더 묶음 — 화면 (PR ①)
**아이디어 모음 (`/ideas`)**
- 제목 아래 칩 줄: `전체 N` · 폴더마다 `이름 N` (이름 가나다순) · 미분류가 있으면 맨 끝 `미분류 N`
- 칩을 누르면 그 폴더만. 고른 칩은 주소 `?folder=이름` (미분류는 `?folder=미분류`, 전체는 없음) → 새로고침 · 뒤로 가기에도 유지
- 없는 폴더 이름이 주소에 오면 전체로 보인다
- 폴더가 하나도 없으면 (전부 미분류) 칩 줄을 숨긴다 — 지금 화면 그대로

**아이디어 카드 (모음 · 홈 "방금 적은 아이디어")** — 폴더가 있으면 진행 배지 옆에 폴더 배지 하나. 카드 전체가 링크라 배지는 누를 수 없다 (링크 안 링크 금지). 걸러내기는 칩 줄로

**폴더 정하기 — 아이디어 폼 (`IdeaForm`, 홈 쓰기 · 상세 수정 공용)**
- 제목 · 메모 아래 `폴더 (선택)` 입력칸. 비우면 미분류
- 입력칸 아래 지금 있는 폴더 칩들 — 누르면 입력칸이 그 이름으로 채워진다 (새 이름은 그냥 적는다)
- 상세 화면 제목 옆에도 폴더 칩 (카드와 같은 모양)

**데모** — 샘플 3개를 폴더 2개로 나눈다 (`일상 추천` · `업무 도구` 같은 일반 이름). 칩 줄 · 카드 칩이 보인다. 폼은 데모라 저장되지 않음 (지금 규칙 그대로)

**안 하는 것** — 폴더 이름 바꾸기 · 지우기 · 끌어 옮기기 · 폴더 안 폴더 · 여러 폴더(태그). 아이디어마다 수정에서 바꾼다
- 갈아탈 신호: 폴더가 10개를 넘거나 "폴더 이름 한 번에 바꾸기" 요청이 오면 폴더 관리 화면을 검토

## 4. 저장 정리 (PR ②)
**생성 문서를 `docs/`로**
```
ideas/<id>/
  idea.md · decisions.md · questions.md   ← 그대로 (사람이 적는 것)
  docs/plan.md … design-prompt.md          ← 생성 문서 (#49 이후 data.md도)
  tools/ · .history/ · .running.json       ← 그대로
```
- `docs.ts`의 `docPath`만 바꾼다: 읽기는 `docs/<file>` → 없으면 예전 자리 `<file>`. 쓰기는 항상 `docs/<file>`. 쓰기 전 `keepHistory`가 두 자리의 지금 판을 `.history/`로 **옮기므로**(지우지 않음 — storage 규칙) 예전 자리에 남는 파일이 없다
- 일괄 이동 스크립트는 없다. 기존 `~/Hatch` 데이터는 문서를 다시 만들거나 고칠 때 하나씩 옮겨진다. 두 자리에 다 있으면 `docs/`가 이긴다
- stale 계산 · 도구 입력 · 요약 판은 `getDocs`를 거치므로 그대로
- `demo-data`는 `git mv`로 `docs/` 아래로 옮긴다 (데모는 읽기 전용이라 자동으로 안 옮겨짐)
- #49와의 관계: #49는 `DOC_STEPS`에 `data` 단계를 더할 뿐이고 경로는 `docPath`를 따른다. 어느 쪽이 먼저 머지돼도 충돌은 `DOC_STEPS` 테스트 수 정도

**자동 목록 파일 `$HATCH_DATA_DIR/목록.md`**
```md
# Hatch 아이디어 목록
자동으로 만든 파일이에요. 고쳐도 다음 저장 때 다시 쓰여요.
```
