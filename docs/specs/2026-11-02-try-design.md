# 흐름 체험 페이지 `/try` 설계 (2026-11-02)

이슈 #75 (refs #63). 사용자 요청: "실제로 돌리는 방식이 아니라 흐름을 데모로 보여줄 수는 없나? 목업으로 예시를 보여주면 되는 거잖아".
공개 데모는 읽기 전용이라 설문 참가자가 설문 과제 7개(`src/lib/survey/questions.ts`의 `TASKS`)를 해 볼 수 없다.

## 1. 결정 (2026-11-02 사용자 확인: 체험 페이지 방식)
- 주소 `/try` 하나. 예시 결과로 과제 7개를 순서대로 해 본다. 실제 생성, 저장, 서버 쓰기는 없다
- 데모와 로컬 모두에서 열린다 (쓰지 않으니 막을 이유가 없다). 네비바에는 넣지 않는다
- 들어오는 길: 데모 배너에 "흐름 체험하기" 링크. 체험 끝에 "설문하러 가기" 버튼(`/survey`)
- 예시 아이디어는 데모 샘플 "동네 원데이 클래스 추천" 하나로 고정. 결과도 이 아이디어의 미리 만든 파일
- 상태는 브라우저 메모리에만. 새로고침하면 처음부터. "처음부터 다시" 버튼을 둔다
- 기다림은 1.5초, 실제와 같은 생성 중 표시(`RunningNote`)를 쓴다. 실제 생성이 1~2분 걸린다는 건 안내 문구로 알린다

## 2. 화면
맨 위 안내(고정): "체험 모드예요. 결과는 미리 만든 예시이고, 아무것도 저장하지 않아요. 실제 생성은 1~2분 걸려요."

그 아래 **과제 표**: 과제 7개를 설문과 같은 문구로 보여 주고, 지금 과제를 강조하고 마친 과제에 체크한다.
설문 문구와 어긋나지 않게 `TASKS`를 내보내 같이 쓴다. 과제 완료는 아래 표의 "마침 조건"으로 코드가 정한다.

| 과제 | 화면 | 마침 조건 |
| --- | --- | --- |
| 1 아이디어 남기기 | 쓰기 폼(`IdeaForm`). 예시 아이디어가 채워져 있다. 고쳐 써도 제목만 바뀌고 결과는 예시 그대로라고 폼 아래에 적는다 | 저장 |
| 2 맥락 적기 | 실제 상세 화면의 맥락 칸(`ContextPanel`) | 맥락 저장 |
| 3 기획안 만들고 지금 내릴 결정 찾기 | 문서 탭의 기획안 만들기 → 요약 판의 "지금 정할 것" | 기획안 생성 |
| 4 확인이 안 된 부분을 질문으로 정리하기 | 질문 칸(`QuestionsPanel`)의 만들기 | 질문 생성 |
| 5 답한 내용을 기획안에 반영하기 | 결정 하나 저장 → 기획안 다시 만들기 | 결정 저장 뒤 기획안 재생성 |
| 6 PRD 검토받고 반론 반영하기 | 체험용 도구 화면 (PRD 리뷰) | 첫 리뷰와 이어 리뷰 |
| 7 고객 의견 정리하기 | 체험용 도구 화면 (VOC) | VOC 실행 |

과제 2~5는 **실제 상세 화면 컴포넌트(`IdeaDetail`)를 그대로** 쓴다. 상세 화면은 모든 행동을 props(함수)로 받으므로,
서버 액션 대신 브라우저 안의 가짜 함수를 넘긴다. 서버가 다시 그려 주던 값(문서, 맥락, 질문, 결정)은 체험 화면이 들고 있고,
요약 판과 질문 목록은 지금처럼 순수 함수(`summarize`, `questionView`, `collectUnknowns`)로 브라우저에서 계산한다.
체험 화면은 `DemoProvider demo={false}`로 감싸 데모에서도 버튼이 보이게 한다.

과제 6, 7은 실제 도구 틀(`ToolFrame`)이 주소(`?result=`)와 서버 새로 그리기에 묶여 있어 그대로 쓰지 않는다.
같은 모양의 작은 체험용 도구 화면을 만든다: 도구 이름과 설명, 입력(PRD 리뷰는 이 아이디어의 PRD, VOC는 붙여 넣은 의견 예시),
실행 버튼, 기다림, 결과(`DocMarkdown`). PRD 리뷰는 결과 아래 "반영하고 다시 검토" 버튼으로 두 번째 예시 결과를 보여 준다.

결과에는 "예시 결과" 배지를 붙인다. 화면 문구에 가운데 점(·)을 쓰지 않는다.

## 3. 상세 화면에서 바꿀 것 (체험에 필요한 만큼만)
- 수정, 휴지통: 체험에서는 숨긴다 (휴지통 확인 문구가 `~/Hatch` 경로를 말해서 맞지 않다). `IdeaDetail`에 선택 prop 하나
- 요약 판과 상세에서 도구, 사용량으로 가는 링크: 체험에서는 체험 안의 도구 단계로 보낸다. 링크 주소를 만드는 함수를 선택 prop으로 받는다.
  안 넘기면 지금과 같다
- 사용량 줄: 체험에서는 넘기지 않는다 (`usage={null}`)

## 4. 예시 결과 만들기
- 읽는 곳: 저장소의 `demo-data/ideas/20261028-1441-n9rp` (기획안부터 프롬프트까지 문서, 질문, PRD 리뷰 2개, VOC). 로컬에서 `HATCH_DATA_DIR`이 무엇이든 같은 예시를 쓰고, 내 데이터는 읽지 않는다
- `/try` 페이지(서버)가 이 폴더를 읽어 체험 화면에 props로 넘긴다
- 처음 상태: 아이디어 제목과 메모만 있고 문서, 맥락, 질문, 결정은 비어 있다
- 기획안 다시 만들기(과제 5): 저장한 결정마다, 예시 기획안의 "확인 필요"에서 같은 질문 줄을 빼고 본문 끝 "정한 것" 절에 `질문: 답`을 넣는다.
  참가자가 고른 답이 그대로 보여야 알아챌 수 있다 (설문 H3). 기획안 판 번호를 올려, 뒤 문서(로드맵, PRD)가 실제처럼 "다시 볼 문서"로 표시되게 한다 (설문 H4)
- 이 변환은 순수 함수로 두고 단위 테스트한다

## 5. 하지 않는 것
- 실제 생성, 저장, 사용량 기록. 체험 행동은 서버로 요청을 보내지 않는다
- 체험 상태를 남기거나 설문 답과 잇기
- 다른 예시 아이디어 고르기, 지표 도구와 협상 도구 체험 (설문 과제에 없다)
