## 1. 근거와 결정 분리 (PR ①)
- 새 파일 `<id>/evidence.md` (머리말 `version: 1`, `items`). 근거 = `{ id, text, source, sourceNote, question, collectedAt }` (질문 없이 적은 근거는 `question: ''`)
  - `source`: `interview` 인터뷰 · `voc` VOC · `survey` 설문 · `teammate` 담당자 확인 · `other` 기타. `sourceNote` = 누구에게 · 언제 (선택, 200자)
  - 고치기 전 판은 `.history/evidence-<시각>.md` (결정과 같은 규칙)
- 결정에 `status: 'proposed'`(제안) 추가, `evidenceIds?: string[]`(연결된 근거). 예전 결정은 그대로 읽힌다 (칸이 없으면 연결 없음)
  - 기획안 입력의 "정한 것"에는 `decided`만, "보류"에는 `deferred`만. 제안은 넣지 않는다
- 확인 질문 `kind`에 `decision`(팀이 정할 것) 추가. 고객(`customer`) · 담당자 확인(`owner`)의 답은 **근거**로, `decision`은 **결정**으로 적는다. 줄마다 다른 쪽으로 적는 보조 버튼도 둔다
  - 예전 `questions.md`(customer · owner만)는 그대로 읽힌다. 프롬프트가 세 가지로 나누게 바꾼다
- 근거 저장 뒤 같은 자리에 "이 근거로 결정을 내릴까요?" + `결정 적기` · `나중에`. 근거만 저장해도 끝
- 결정 수 · "정한 것" · 결정 탭 숫자는 결정만 센다. 근거 수는 따로 보인다 (현황 4칸: 문서 · 확인 질문 · 근거 · 결정)
- PR ①에선 근거를 기획안 입력에 넣지 않는다 (근거만 적어도 "앞 문서가 바뀌었어요"가 뜨지 않게). "확인한 근거" 블록은 변경 원인을 나눠 보이는 PR ②에서 더한다. 근거가 없으면 블록이 없어 기존 해시는 그대로
- 제안한 결정은 "아직 안 정한 것" 목록에서 빠지고 "남긴 결정"에 `제안` 배지로 보인다 (같은 질문이 두 곳에 나오지 않게). 결정 수에는 세지 않는다
- 예전에 고객 답으로 저장된 결정은 옮기지 않는다 (어느 것이 근거였는지 코드로 알 수 없음)

## 2. 변경 원인 · 비교 후 반영 · 이전 버전 (PR ②)
- 문서 머리말에 `inputs`(입력별 해시: `idea` 아이디어 · 맥락, `decisions`, `evidence`, 앞 문서 키마다) 추가. `sourceHash`는 그대로 둔다
- `Doc`에 `changes: ('doc:<key>' | 'idea' | 'decisions' | 'evidence' | 'unknown')[]`. `inputs`가 없는 예전 문서는 `sourceHash`로만 비교하고 원인은 `unknown`
- 알림 문구: 앞 문서 → "앞 문서(○○)가 바뀌었어요" · 근거 → "근거가 추가되어 검토해야 해요" · 결정 → "결정이 바뀌었어요" · 맥락 → "아이디어나 맥락이 바뀌었어요" · 모름 → "만든 뒤 입력이 바뀌었어요"
  - 앞 문서가 바뀌지 않았는데 앞 문서 자체가 예전 기준이면 배지 없이 "○○을 먼저 검토하세요" 한 줄
- 이미 있는 문서를 다시 만들면 **초안** `<id>/drafts/<key>.md`에 저장하고 바로 덮지 않는다
  - 카드에 비교: 바뀐 절(`## `) 목록, 더한 · 뺀 줄, 새 근거 · 결정. 버튼 `적용` · `고쳐서 적용` · `지금 판 유지`
  - 적용하면 지금 판은 이전 버전으로 간다. 유지하면 초안을 이전 버전 폴더로 옮긴다 (지우지 않음)
  - 손으로 고친 문서(`editedAt`)면 적용 전에 "직접 고친 내용이 있어요"를 알린다
  - 실패하면 지금 문서와 초안 모두 그대로
- 화면 문구에서 `.history` 대신 "이전 버전". 카드에 `이전 버전 보기 (N)` → 시각 목록 → 읽기 전용 본문 + 지금 판과 비교. 되돌리기는 이번에 넣지 않는다
- 비교는 줄 단위 LCS (의존성 없이 `src/lib/diff.ts`, 순수 · 테스트)

## 3. 생성 ≠ 준비 · 먼저 볼 미해결 (PR ③)
- "완료" → "생성됨" (목록 카드 `7/7 생성됨`, 탭 요약, 탭 상태). 카드에 실제 데이터가 있을 때만 `근거 N` · `결정 N` · `PRD 리뷰함` 배지
- 먼저 볼 미해결: 점수를 만들지 않는다. 있는 데이터로만 순서를 정하고 그 기준을 화면에 적는다
  - 팀이 정할 것(질문 `decision` · 기획안 "확인 필요" 절의 안 정한 것) 먼저, 그다음 [확인 필요]가 걸린 곳 수가 많은 순 (기존 `countUnknowns`)
  - 상위 5개만 보이고 `모두 보기`로 전부
## 4. 권장 순서 · 막지 않기 (PR ③)
- 앞 문서가 없어도 만들 수 있다: 가장 가까운 있는 앞 문서(없으면 아이디어)로 만들고, 무엇이 빠졌는지 보인 뒤 `지금 자료로 만들기` 확인. 빠진 `extra`도 같은 방식
- 만든 문서 머리말 `inputs`에 실제로 쓴 입력이 남아, 화면에 "개발 로드맵 없이 기획안으로 만들었어요"
- 도구: 아이디어에 받는 문서가 없으면 이유와 `붙여넣기로 계속`을 보인다. 체험 PRD 리뷰는 예시 PRD로 계속할 수 있다

## 5. 데모 첫 화면 · VOC 샘플 (PR ④)
- 데모 홈: 저장 폼 대신 `흐름 체험하기`(주) · `완성된 예시 보기`(보조) · 읽기 전용 안내. 로컬은 그대로
- VOC 결과 `data.lines`에 분석한 입력 원문을 저장. 결과 화면에 접힌 `분석에 사용한 VOC 보기 (N줄)`. `lines`가 없는 예전 결과는 "이 결과에는 입력 원문이 저장되지 않았어요"
- 데모 · 체험 샘플: 남아 있는 대표 의견 15줄로 VOC를 실제로 다시 돌려 새 결과 파일을 만든다 (옛 파일은 남김). 건수 · 입력 · 결과가 한 파일에서 나온다. 의견을 지어내지 않는다
- 데모 도구 화면의 입력 칸은 읽기 전용으로 결과의 입력을 보인다

## 6. 지금 목표 · 다음 행동 한 줄 (PR ④)
- 체험: `tryNext(state)` 하나가 지금 과제와 그 과제의 주 행동을 정한다. 위 과제 목록의 "지금", 상세 "다음 할 일", 도구 화면의 버튼이 모두 이 값을 쓴다. "그다음"은 한 줄로 따로
- 상세(실제): `nextOf`가 `then`(그다음 하나)도 돌려준다. 근거가 추가된 문서는 "근거를 보고 ○○ 검토하기"
- 실제로 없는 기능을 되는 것처럼 보이지 않는다 (데모 버튼은 `내 환경에서 사용하기`)

## 7. 그대로 둘 것
VOC 출발 순위 설명, 협상 도구의 근거 없는 숫자 찾기, 지표 · 실험의 이유 · 편향 설명. 해당 화면은 VOC 입력 보기 말고는 건드리지 않는다.
