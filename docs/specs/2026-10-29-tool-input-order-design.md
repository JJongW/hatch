# 도구 입력 순서 · 점수 낮추기 설계 (2026-10-29)

피드백 5 · 8 · [반영 계획](../plans/2026-10-29-feedback.md) 3단계. 이슈 #41.
도구 화면이 "입력 문서 → 도구 입력" 한 가지 순서라, VOC는 정작 중요한 고객 의견이 아래에 있고 협상은 아직 받지도 않은 요청에 대한 "내 답" 칸이 먼저 보인다. VOC · 협상 결과는 AI 판단을 계산한 점수가 맨 앞이라, 사람이 정할 우선순위 · 판단이 점수에 묻힌다.

## 1. 결정 (2026-10-29 사용자 확인)
- VOC "사람이 우선순위를 정한다"는 이번엔 **보여 주기만**: 출발 순위 + 사람이 볼 질문. 사람이 고른 순위 · 이유 저장은 4a(결정 기록)에서
- PRD 리뷰 · 지표 도구는 바꾸지 않는다

## 2. VOC — 고객 의견 먼저 (피드백 5)
- 화면 순서: **고객 의견**(도구 입력) → **제품 맥락 (선택)**(아이디어 문서 · 직접 붙여넣기 · 문서 없이) → 실행
- 처음 고른 값: URL에 아이디어가 없으면 **문서 없이**. `?idea=`로 오면(상세 화면의 "고객 의견 정리하기") 그 아이디어 · 기본 문서(기획안)
- 붙여넣기는 `?source=pasted`로 구분한다 (지금은 파라미터 없음 = 붙여넣기). 기존 붙여넣기 결과 링크(`?result=`만)는 문서 없이 탭으로 열려 결과를 못 찾으면 그 탭의 최신 결과를 보인다 — 로컬 앱이라 감수
- 기준: `ToolDef.sourceOptional`(문서 없이 실행 가능 = 지금 VOC만)이면 입력 먼저 · 기본 문서 없이. 두 성질이 갈리는 도구가 생기면 플래그를 나눈다
- 칸 제목: 도구 입력 칸은 `ToolDef.inputLabel`(VOC '고객 의견', 기본 '도구 입력'), 문서 칸은 sourceOptional이면 '제품 맥락 (선택)', 아니면 '입력 문서'

## 3. 협상 — 내 답은 1라운드 뒤 (피드백 5)
- 처음 화면엔 "내 답" 칸이 없다. 실행 → 상대 요청이 결과로 나온다
- 결과 상자 안, 본문 아래에 **내 답 칸 + "내 답 보내기"**. 프레임에 `continueFields`(결과 상자 안 이어 실행 입력) 자리를 더한다
- 결과 본문은 **다음 요청이 맨 끝**에 오도록 순서를 바꿔 바로 아래 답 칸과 붙인다
- 위쪽 "실행"은 새 협상(1라운드). 결과가 있을 때 답 칸에 글을 쓰고 위 "실행"을 누르면 지금처럼 "1라운드는 내 답 없이 시작해요" 안내
- 데모: 지금처럼 결과 안 이어 실행 영역(답 칸 · 버튼)을 보이지 않는다

## 4. 점수 낮추기 (피드백 8)
**VOC 결과** (계산 · 저장 형식 그대로, 본문만)
```
## 요약           VOC N건 · 주제 M개 · 분류 안 됨 K건
## 출발 순위       건수 × 평균 심각도로 매긴 출발점이에요. 실제 우선순위는 아래 질문을 보고 정해요.
                  - **1** 결제 — 건수 2 · 평균 심각도 4 (합 8)
## 순위를 정하기 전에 볼 것
                  - 고객군: 이 불만은 어느 고객군에서 나왔고, 그 고객군이 지금 목표 고객인가?
                  - 제품 목표: 고치면 이번 목표 지표가 움직이나?
                  - 해결 비용: 고치는 데 얼마나 드나? 작게 먼저 풀 방법이 있나?
## 주제별 대표 VOC  ### 1 · 결제 (설명 · 건수 · 평균 심각도 · 대표 VOC는 그대로)
## 분류 안 됨       그대로
```
- "점수" · "위" 표기를 뺀다. 같은 합이면 같은 번호(지금 rank 그대로)

**협상 결과** — 순서: 상대 → N라운드 내 답 → 상대 반응 → 피드백 → **참고 점수** → 지난 대화 → 다음 요청(맨 끝, "아래에 내 답을 적고 '내 답 보내기'")
- `## 점수 · …` → `## 참고 점수 · …` (내용 · 변화 · 평균 그대로). 1라운드는 지금처럼 점수 칸 없음

**도구 설명 문구**
- VOC: "VOC를 한 줄에 하나씩 붙여넣으면 주제로 묶고 건수 × 심각도로 출발 순위를 매겨요. 최종 우선순위는 고객군 · 목표 · 비용을 보고 직접 정해요."
- 협상: "문서와 부딪히는 요청을 하는 이해관계자와 라운드마다 협상을 연습해요. 상대 반응과 피드백을 보고 답을 다듬어요. 점수는 참고로만 보여 줘요."

**이미 만든 결과**: 결과 파일의 `body`는 만들 때 저장된 본문이다. `demo-data/`의 VOC · 협상 결과는 저장된 `data`로 `render`를 다시 돌려 `body`만 바꾼다(일회성 스크립트, 커밋하지 않음). 사용자 `~/Hatch`의 기존 결과는 건드리지 않는다 (새로 실행하면 새 형식)

## 5. 구조
- `src/lib/tools/types.ts` — `inputLabel?: string` 추가
- `src/app/tools/_frame/load.ts` — `none` 판정(sourceOptional이면 `source !== 'pasted'`일 때 기본 none), `tool.inputLabel` 넘김
- `src/app/tools/_frame/tool-frame.tsx` — sourceOptional이면 입력 칸 먼저 · 칸 제목, 붙여넣기 링크 `?source=pasted`, `continueFields` 자리
- `src/lib/tools/voc/` · `negotiation/` — render · 설명 · `inputLabel`
- `src/app/tools/negotiation/` — 답 칸을 `continueFields`로, 안내 문구
- 공통 틀 변경이지만 이 기능만을 위한 것이라 한 PR로 (도구 병렬 작업 중이 아님)
