# 모션 설계: 생성 대기, 목록 등장, 누를 수 있는 것 반응 (2026-11-02)

이슈 #77. 사용자 요청: "내가 원했던 모션의 효과가 지금 하나도 적용되어 있지 않음". 지금 모션은 로고 Hatch↔해치 전환 하나뿐이다.
근거는 2026-10-29 조사 보고서(beautifului, aicss) 1번 "문서 생성 대기 화면"과 ui-ux-pro-max 검색 결과다.
사용자가 고른 것: 생성 대기 화면, 목록 차례로 나타나기, 누를 수 있는 것 반응. 문서 체인 진행 표시는 #78로 따로 한다.

## 1. 생성 대기 화면 (`RunningNote`)
문서 생성과 도구 실행은 1~2분 걸린다. 지금은 회전 아이콘, 문구, 지난 시간만 있어서 멈춘 건지 도는 건지 알기 어렵다.
- 문구에 반짝임(shimmer)을 준다. 글자 위로 밝은 띠가 1.6초마다 지나간다
- 지난 시간은 지금처럼 보여 준다
- **예상 순서**를 한 줄씩 올린다. 예: 기획안은 "아이디어 읽기 → 문제와 대상 정리 → 핵심 가치와 기능 → 지표와 위험 → 모르는 것 표시"
  - `claude -p`는 중간 진행을 알려 주지 않는다. 그래서 진짜 진행률이 아니라 **예상 순서**라고 적는다 ("예상 순서예요. 실제 진행과 다를 수 있어요")
  - 단계는 예상 시간(60초)에 고르게 나눠 하나씩 나타난다. 마지막 단계는 끝날 때까지 남는다
  - 새 단계는 아래에서 4px 올라오며 0.35초 동안 나타난다. 지금 단계만 진한 글씨로 보인다
- 문서별 단계 문구는 `src/app/_components/running-steps.ts`에 둔다. 도구별 단계는 도구 정의에 `runningSteps`를 더한다 (`runningLabel` 옆)
- **끝나면 접힌다**: 문서 카드에 "1분 12초 걸려 만들었어요" 한 줄이 남는다. 누르면 예상 순서를 펼쳐 본다 (여기에도 "예상 순서" 고지를 단다). 도구는 결과 화면으로 넘어가므로 접는 줄을 두지 않는다

## 2. 목록 차례로 나타나기
- 아이디어 목록(홈의 방금 적은 아이디어, 아이디어 모음)의 카드가 위에서부터 차례로 나타난다
- 한 칸마다 아래에서 8px 올라오며 0.3초. 다음 칸은 0.03초 뒤에 시작하고, 10번째부터는 더 늦추지 않는다 (긴 목록이 굼떠 보이지 않게)
- 문서 탭을 바꾸면 내용이 0.2초 동안 페이드된다

## 3. 누를 수 있는 것 반응
- 아이디어 카드: 마우스를 올리면 배경이 0.2초에 걸쳐 바뀐다 (카드에 테두리가 없다). 누르는 순간 살짝(0.99) 줄어든다
- 네비 항목: Montage ListCell이 이미 마우스를 올리면 0.15초에 걸쳐 배경층을 띄운다. 더 넣지 않는다
- 키보드 포커스 표시는 그대로 둔다

## 4. 공통 규칙
- **줄인 모션 설정(prefers-reduced-motion)** 을 켠 사람에게는 반짝임, 올라오기, 페이드를 모두 끄고 바로 최종 모습을 보여 준다. 예상 순서 글자는 그대로 보인다
- 애니메이션은 CSS(`@keyframes`)로만 한다. 로고처럼 순서 제어가 필요한 경우에만 gsap을 쓴다
- 색은 Montage 토큰만 쓴다. 화면 문구에 가운데 점(·)을 쓰지 않는다

## 5. 하지 않는 것
- 진짜 진행률 (claude -p가 주지 않는다)
- 페이지 이동 애니메이션, 스크롤에 따라 나타나기 (읽는 앱이라 방해가 된다)

## 6. 검증
- 단위: 단계 공개 계산(지난 초 → 보일 단계 수)
- 브라우저: 일반 모드에서 실제 생성 한 번 (대기 화면, 접는 줄), 데모 모드에서 목록과 호버, 줄인 모션 설정 켜고 다시 확인, 휴대폰 폭, 콘솔 오류
- `npm run lint && npm run typecheck && npm test && npm run build`
