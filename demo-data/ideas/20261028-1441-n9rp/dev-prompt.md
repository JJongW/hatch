3) 추천 목록: 카드 목록. 카드마다 클래스명, 시작 시간, 소요 시간, 가격, 남은 자리, 공방 위치 요약, 선택 가능한 시간대. 동선 요약과 수정 진입점(F12 플래그 따름). 카드가 보이면 노출 이벤트, 카드를 누르면 클릭 이벤트 후 상세로, 시간대를 누르면 클릭 이벤트 후 예약 진행으로 간다. 결과가 없으면 빈 상태 안내를 보인다.
4) 클래스 상세: 클래스명, 대표 이미지([확인 필요: 클래스 이미지 확보], 없을 때 대체 표시), 소요 시간, 가격, 준비물, 남은 자리, 공방 위치와 지도, 퇴근길 이동 정보, 시간대 목록, 예약하기 버튼. 고른 시간대를 강조한다. 마감 시간대는 선택 불가로 표시한다. 뒤로 가기는 추천 목록으로 간다.
5) 예약 진행: 클래스명, 날짜, 시간대, 가격 요약. 서비스 안 예약이면 예약자 정보 입력([확인 필요: 예약과 결제 처리 방식])과 예약 확정 버튼, 확정 시 예약 완료 화면으로 간다. 공방 채널이면 이동 안내와 이동 버튼, 누르면 채널을 연다. 직전 마감이면 마감 안내 후 시간대를 다시 고르게 한다.
6) 예약 완료: 완료 안내, 클래스명, 날짜, 시간대, 공방 위치, 준비물, 추천 목록으로 돌아가기. 열리면 예약 완료 이벤트를 기록한다.
7) 운영 클래스 관리(운영자 전용): 공방 목록과 등록 버튼, 공방 폼(공방명, 위치, 예약 채널 정보), 클래스 폼(클래스명, 분야, 소요 시간, 가격, 준비물), 일정 폼(날짜, 시간대, 정원, 남은 자리), 노출 여부, 마지막 수정 시각. 저장 내용은 추천 목록과 상세에 반영된다. 필수 누락이나 형식 오류는 저장하지 않고 오류 항목을 표시한다.
8) 예약 전환율 대시보드(운영자 전용): 기간 필터, 노출 수, 클릭 수, 예약 완료 수, 전환율, 클릭률, 목표값, 데이터 갱신 시각. 기간을 바꾸면 다시 집계해 보인다. 권한이 없으면 접근 불가 안내를 보인다.
9) 내 설정 수정(F12 플래그): 현재 취향, 회사 위치, 집 위치, 퇴근 시간, 저장 버튼. 저장하면 추천 목록을 새로 만든다. 필수 값이 비면 저장하지 않고 안내한다.

[완료 기준]
1) F1~F12의 정상 흐름과 위에 적은 예외마다 자동 테스트가 있고 모두 통과한다.
2) 사용자 흐름 취향 설정, 동선 입력, 추천 목록, 상세, 예약 진행, 예약 완료가 목 외부 서비스로 끝까지 동작하는 통합 테스트가 있다.
3) 노출, 클릭, 예약 완료 이벤트가 같은 추천 ID로 이어지고, 대시보드 수치가 테스트 데이터 기대값과 맞는다.
4) 동시 예약 요청에서 남은 자리가 음수가 되지 않는다.
5) 운영자 아닌 계정은 운영 클래스 관리와 대시보드에 접근할 수 없다.
6) 모든 [확인 필요] 정책이 설정이나 교체 가능한 함수로 분리되어 있고, README에 미결 목록과 현재 임시 기본값이 정리되어 있다.
7) 결제 처리 코드가 없다.
8) README에 실행, 테스트, 시드 데이터 넣는 방법이 있다.

## 기술 가정
- 모바일 웹 우선의 웹 앱으로 만든다 [확인 필요]
- 언어는 TypeScript를 쓴다 [확인 필요]
- 프레임워크는 Next.js 하나로 사용자 화면, 운영 화면, API를 함께 만든다 [확인 필요]
- 저장소는 PostgreSQL을 쓰고 ORM은 Prisma를 쓴다 [확인 필요]
- 단위와 통합 테스트는 Vitest, 화면 흐름 테스트는 Playwright를 쓴다 [확인 필요]
- 지도, 위치 검색, 경로 계산은 인터페이스 뒤에 두고 개발과 테스트에서는 목 구현을 쓴다. 실제 제공 서비스는 정하지 않는다 [확인 필요]
- 로그인 방식이 정해지기 전까지 사용자는 기기 단위 익명 ID로 구분한다 [확인 필요]
- 운영자 인증은 이메일과 비밀번호 로그인과 역할 값 하나로 처리한다 [확인 필요]
- 이벤트는 별도 분석 도구 없이 같은 데이터베이스 이벤트 테이블에 저장한다 [확인 필요]
- 전환율 집계는 조회 시점 쿼리로 계산하고 갱신 시각을 함께 돌려준다 [확인 필요]
- 모든 시각은 Asia/Seoul 기준으로 저장하고 표시한다 [확인 필요]
- 출시 지역 안 판정은 지역 경계 데이터와 좌표 비교로 한다 [확인 필요]
