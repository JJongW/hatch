### 취향 설정 화면
처음 이용하는 사용자가 최소한의 취향 정보를 입력한다. (R1)

**구성 요소**
- 화면 제목과 짧은 안내 문구
- 취향 입력 항목. 항목 구성은 [확인 필요: 취향 입력 항목]
- 예산 입력 영역. 사용자 스토리에 예산이 예시로 있으나 항목 확정은 [확인 필요: 취향 입력 항목]
- 다음 버튼

**동작**
- 사용자가 취향 항목을 고른다. 고른 값이 화면에 표시된다.
- 필수 항목을 채우고 다음을 누른다. 취향 정보가 저장되고 동선 입력 화면으로 이동한다.
- 필수 항목을 비운 채 다음을 누른다. 빈 항목을 알리는 안내가 보이고 이동하지 않는다. 필수 여부는 [확인 필요: 필수 항목 범위]

### 동선 입력 화면

**구성 요소**
- 회사 위치 입력 필드
- 집 위치 입력 필드
- 위치 검색 결과 목록
- 퇴근 시간 선택 필드
- 위치 정보 이용 동의 안내. 필요 여부는 [확인 필요: 개인정보 동의 정책]
- 추천 받기 버튼

**동작**
- 사용자가 회사 위치를 검색하고 결과를 고른다. 선택한 위치가 필드에 표시된다.
- 사용자가 집 위치를 검색하고 결과를 고른다. 선택한 위치가 필드에 표시된다.
- 사용자가 퇴근 시간을 고른다. 선택한 시간이 필드에 표시된다.
- 세 항목을 모두 채우고 추천 받기를 누른다. 동선 정보가 저장되고 추천 목록 화면으로 이동한다.
- 입력한 위치가 첫 출시 지역 밖이다. 서비스 지역이 아니라는 안내가 보인다. 처리 방식은 [확인 필요: 지역 밖 입력 처리]

### 추천 목록 화면
사용자가 취향과 퇴근길 동선에 맞는 클래스 추천을 보고 고른다. (R3, R5, R7, R10)

**구성 요소**
- 추천 클래스 카드 목록
- 카드별 클래스명, 시작 시간, 소요 시간, 가격, 남은 자리, 공방 위치 요약
- 카드별 선택 가능한 시간대
- 입력한 동선 요약과 수정 진입점. 수정 기능 포함 여부는 [확인 필요: R9 MVP 포함 여부]
- 결과가 없을 때 빈 상태 안내. 문구와 대안 제시 방식은 [확인 필요: 빈 결과 처리 방식]

**동작**
- 화면에 추천 카드가 보인다. 추천 노출 이벤트가 기록된다.
- 사용자가 카드를 누른다. 추천 클릭 이벤트가 기록되고 클래스 상세 화면으로 이동한다.
- 사용자가 카드에서 시간대를 고른다. 추천 클릭 이벤트가 기록되고 예약 진행 화면으로 이동한다.
- 추천 결과가 없다. 빈 상태 안내가 보인다.

### 클래스 상세 화면

**구성 요소**
- 클래스명과 대표 이미지. 이미지 제공 여부는 [확인 필요: 클래스 이미지 확보]
- 소요 시간
- 가격
- 준비물
- 남은 자리
- 공방 위치와 지도
- 퇴근길 기준 이동 정보. 표시 항목은 [확인 필요: 동선 정보 표시 방식]
- 선택 가능한 시간대 목록
- 예약하기 버튼

**동작**
- 사용자가 시간대를 고른다. 선택한 시간대가 강조된다.
- 사용자가 예약하기를 누른다. 예약 진행 화면으로 이동한다.
- 남은 자리가 없는 시간대다. 해당 시간대는 선택할 수 없게 표시된다.
- 사용자가 뒤로 가기를 누른다. 추천 목록 화면으로 돌아간다.

### 예약 진행 화면
사용자가 고른 시간대로 예약을 마치거나 공방 예약 채널로 넘어간다. (R5)

**구성 요소**
- 선택한 클래스명, 날짜, 시간대, 가격 요약
- 서비스 안 예약 시 예약자 정보 입력 영역. 입력 항목은 [확인 필요: 예약과 결제 처리 방식]
- 공방 채널 연결 시 이동 안내 문구와 이동 버튼
- 예약 확정 버튼

**동작**
- 서비스 안 예약 방식이다. 사용자가 예약 확정을 누른다. 예약 요청이 저장되고 예약 완료 화면으로 이동한다.
- 공방 채널 연결 방식이다. 사용자가 이동 버튼을 누른다. 공방 예약 채널이 열린다.
- 예약 직전 남은 자리가 없어졌다. 마감 안내가 보이고 다른 시간대를 고르게 한다.

### 예약 완료 화면

**구성 요소**

- 클래스명, 날짜, 시간대, 공방 위치
- 준비물
- 추천 목록으로 돌아가기 버튼

**동작**
- 화면이 열린다. 예약 완료 이벤트가 기록된다.
- 사용자가 돌아가기를 누른다. 추천 목록 화면으로 이동한다.

- 노출 여부 설정
- 마지막 수정 시각

**동작**

- 운영자가 남은 자리를 고친다. 상세 화면과 추천 목록에 반영된다.
- 필수 항목이 비었거나 형식이 틀렸다. 저장되지 않고 오류 항목이 표시된다.

- 추천 노출 대비 클릭률

- 필수 값을 비우고 저장한다. 저장되지 않고 안내가 보인다.

## 기능
### F1. 취향 정보 저장
- **입력** 사용자 ID, 취향 입력값. 항목은 [확인 필요: 취향 입력 항목]
- **처리** 필수 항목이 채워졌는지 확인한다. 사용자 프로필에 취향 정보를 저장한다.
- **출력** 저장된 취향 정보. 동선 입력 단계로 진행 가능 상태

**예외**
- 필수 항목이 비었다. 저장하지 않고 빈 항목을 알린다.
- 허용하지 않는 값이 들어왔다. 저장하지 않고 오류를 돌려준다.
- 저장에 실패했다. 다시 시도하라는 안내를 보여 준다.

### F2. 동선 정보 저장
- **입력** 사용자 ID, 회사 위치, 집 위치, 퇴근 시간
- **처리** 위치 검색 결과를 좌표로 바꾼다. 위치가 첫 출시 지역 안인지 확인한다. 퇴근 시간 형식을 확인한다. 사용자 프로필에 저장한다.
- **출력** 저장된 회사 위치, 집 위치, 퇴근 시간

**예외**
- 세 항목 중 하나라도 비었다. 저장하지 않는다.
- 위치를 찾을 수 없다. 다시 입력하게 한다.
- 위치가 첫 출시 지역 밖이다. 처리 방식은 [확인 필요: 지역 밖 입력 처리]
- 위치 정보 이용에 동의하지 않았다. 처리 방식은 [확인 필요: 개인정보 동의 정책]

### F3. 퇴근길 동선 계산
- **입력** 회사 위치, 집 위치, 퇴근 시간, 공방 위치
- **처리** 회사에서 집까지의 경로를 구한다. 각 공방이 경로에서 들를 수 있는 범위인지 판단한다. 퇴근 시간 이후 도착 가능한 시각을 구한다. 경로 기술은 [확인 필요: 지도와 경로 기술 선택]. 들를 수 있는 범위의 기준은 [확인 필요: 우회 허용 기준]
- **출력** 공방별 퇴근길 경유 가능 여부와 예상 도착 시각

**예외**
- 경로 계산 서비스가 응답하지 않는다. 처리 방식은 [확인 필요: 경로 계산 실패 시 대체 방식]
- 회사와 집 위치가 같다. 처리 방식은 [확인 필요: 동일 위치 처리]

### F4. 클래스 추천 목록 생성
- **입력** 사용자 ID, 취향 정보, 퇴근길 동선 계산 결과, 첫 출시 지역 클래스 일정 데이터
- **처리** 노출 상태이고 남은 자리가 있는 일정만 고른다. 퇴근 후 도착 가능한 시간대의 일정만 고른다. 취향과 예산에 맞는 클래스만 고른다. 정렬 기준은 [확인 필요: 추천 정렬 기준]. 추천 단위마다 추천 ID를 붙인다.
- **출력** 추천 클래스 목록과 클래스별 선택 가능한 시간대, 추천 ID

**예외**
- 조건에 맞는 클래스가 없다. 빈 결과를 돌려주고 빈 상태 안내를 보여 준다. 처리 방식은 [확인 필요: 빈 결과 처리 방식]
- 취향 또는 동선 정보가 없다. 해당 입력 화면으로 보낸다.
- 데이터 조회에 실패했다. 다시 시도 안내를 보여 준다.

### F5. 클래스 상세 조회
- **입력** 클래스 ID, 추천 ID, 사용자 동선 정보
- **처리** 클래스의 소요 시간, 가격, 준비물, 남은 자리, 공방 위치, 시간대를 한 번에 가져온다. 퇴근길 기준 이동 정보를 붙인다.
- **출력** 클래스 상세 정보와 시간대별 남은 자리

**예외**
- 클래스가 비노출 또는 삭제 상태다. 더 이상 볼 수 없다는 안내를 보여 준다.
- 준비물 등 일부 항목이 비었다. 표시 방식은 [확인 필요: 빈 항목 표시 정책]
- 모든 시간대의 남은 자리가 없다. 예약 버튼을 비활성화한다.

### F6. 예약 처리 또는 공방 채널 연결
- **입력** 사용자 ID, 클래스 ID, 선택한 시간대, 추천 ID, 예약 방식
- **처리** 선택한 시간대의 남은 자리를 다시 확인한다. 서비스 안 예약 방식이면 예약 요청을 저장하고 상태를 완료로 바꾼다. 공방 채널 방식이면 이동 기록을 남기고 공방 예약 채널을 연다. 적용 방식은 [확인 필요: 예약과 결제 처리 방식]. 결제는 직접 처리하지 않는다.
- **출력** 예약 기록과 예약 상태, 또는 공방 채널 이동 기록

**예외**
- 예약 직전 남은 자리가 없다. 마감 안내를 보여 주고 다른 시간대를 고르게 한다.
- 공방 채널 정보가 없다. 처리 방식은 [확인 필요: 채널 정보 누락 처리]
- 중복 예약 요청이 들어왔다. 처리 방식은 [확인 필요: 중복 예약 정책]
- 공방 채널로 넘어간 뒤 실제 완료 여부를 알 수 없다. 집계 방식은 [확인 필요: 예약 완료 측정 방식]

### F7. 추천 이벤트 수집
- **입력** 이벤트 종류(추천 노출, 추천 클릭, 예약 완료), 사용자 ID, 추천 ID, 클래스 ID, 시간대, 발생 시각
- **처리** 추천 카드가 화면에 보이면 노출 이벤트를 기록한다. 카드나 시간대를 누르면 클릭 이벤트를 기록한다. 예약이 완료되면 예약 완료 이벤트를 기록한다. 세 이벤트는 추천 ID로 연결한다. 노출 판정 기준은 [확인 필요: 노출 집계 기준]
- **출력** 저장된 이벤트 기록

**예외**
- 이벤트 전송에 실패했다. 재전송 방식은 [확인 필요: 이벤트 유실 처리]
- 같은 이벤트가 중복으로 들어왔다. 중복 제거 기준은 [확인 필요: 중복 이벤트 기준]
- 추천 ID가 없는 예약 완료다. 추천 경유 예약에서 제외할지 [확인 필요: 귀속 기준]

### F8. 예약 전환율 집계
- **입력** 추천 노출, 추천 클릭, 예약 완료 이벤트, 조회 기간
- **처리** 추천 클릭 후 예약 완료로 이어진 비율을 구한다. 추천 노출 대비 클릭 비율을 구한다. 분모와 분자의 단위(사용자 또는 클릭)는 [확인 필요: 전환율 정의]. 클릭 후 예약을 인정하는 기간은 [확인 필요: 귀속 기간]
- **출력** 기간별 노출 수, 클릭 수, 예약 완료 수, 예약 전환율, 클릭률

**예외**
- 기간 안에 클릭이 없다. 전환율을 계산하지 않고 데이터 없음으로 표시한다.
- 공방 채널 예약 완료가 아직 확인되지 않았다. 표시 방식은 [확인 필요: 예약 완료 측정 방식]

### F9. 대시보드 조회
- **입력** 운영자 계정, 조회 기간
- **처리** 운영자 권한을 확인한다. 집계 결과를 가져와 보여 준다.
- **출력** 예약 전환율 대시보드 화면 데이터

**예외**
- 권한이 없다. 접근을 막는다. 권한 범위는 [확인 필요: 대시보드 접근 권한]
- 집계가 늦어졌다. 마지막 갱신 시각을 함께 보여 준다. 갱신 주기는 [확인 필요: 집계 주기]

### F10. 클래스 데이터 등록과 수정
- **입력** 운영자 계정, 공방 정보, 클래스 정보, 일정, 정원, 남은 자리, 노출 여부
- **처리** 운영자 권한을 확인한다. 필수 항목과 형식을 확인한다. 공방 위치가 첫 출시 지역 안인지 확인한다. 저장하고 마지막 수정 시각을 남긴다. 데이터 확보 방식은 [확인 필요: 첫 출시 지역과 데이터 확보 방식]
- **출력** 저장된 공방, 클래스, 일정 데이터

**예외**
- 필수 항목이 비었다. 저장하지 않는다.
- 공방 위치가 첫 출시 지역 밖이다. 저장하지 않는다.
- 남은 자리가 정원보다 크거나 음수다. 저장하지 않는다.
- 지난 일정이다. 추천 대상에서 뺀다.

### F11. 남은 자리 갱신
- **입력** 일정 ID, 남은 자리 값, 갱신 주체
- **처리** 운영자 입력 또는 서비스 안 예약 완료 시 남은 자리를 바꾼다. 갱신 시각을 남긴다. 갱신 방법과 주기는 [확인 필요: 남은 자리 동기화 방식]
- **출력** 갱신된 남은 자리와 갱신 시각

**예외**
- 공방 쪽 실제 잔여석과 다르다. 처리 방식은 [확인 필요: 불일치 처리 정책]
- 남은 자리가 0이 되었다. 해당 시간대를 선택 불가로 바꾼다.

### F12. 사용자 설정 수정
- **입력** 사용자 ID, 수정한 취향 정보, 회사 위치, 집 위치, 퇴근 시간
- **처리** 취향 정보 저장과 동선 정보 저장과 같은 검증을 한다. 저장 후 추천 목록을 다시 만든다. P1이며 MVP 포함 여부는 [확인 필요: MVP 포함 여부]
- **출력** 수정된 사용자 설정과 새 추천 목록

**예외**
- 필수 값이 비었다. 저장하지 않는다.
- 수정한 위치가 첫 출시 지역 밖이다. 처리 방식은 [확인 필요: 지역 밖 입력 처리]

- 퇴근길에 들를 수 있다는 기준은 무엇인가? 우회 허용 거리나 시간, 퇴근 후 몇 시간 안의 일정까지 볼지 정해야 한다.

- 입력한 회사나 집 위치가 첫 출시 지역 밖일 때 이용을 막는가, 대기 안내를 하는가?

- 회사와 집 위치 수집에 필요한 개인정보 동의 절차와 보관 기간은 무엇인가?
- 추천 노출은 언제 한 번으로 세는가? 목록 응답 시점인가, 카드가 화면에 보인 시점인가?
- 예약 전환율의 분모와 분자를 사용자 단위로 볼지, 클릭 단위로 볼지 정해야 한다.
- 클릭 후 얼마 안에 일어난 예약까지 추천 경유 예약으로 인정하는가?
- 예약 전환율 목표값과 클릭률 목표값은 얼마인가?

- MVP 개발 전에 수요 조사와 퇴근 시간대 공급 현황 조사를 먼저 하는가?
- MVP 개발 기간과 출시 일정은 어떻게 잡는가?
