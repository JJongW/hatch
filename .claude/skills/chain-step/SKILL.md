# 체인 단계 하나 추가하기

> 단계 파일의 정확한 모양은 B spec에서 확정한다. 확정되면 아래 경로 · 타입 이름을 갱신한다.

## 전제
- 앞 단계가 이미 있다 (첫 단계는 아이디어가 입력)
- 이 단계의 이슈(`area:chain`)와 브랜치가 있다

## 순서
1. **입력 · 출력 정하기** — 입력은 앞 단계 출력 하나. 출력 JSON 스키마를 먼저 쓴다
2. **스키마 테스트** — 정상 예시 통과, 필수 칸 빠진 예시 실패
3. **프롬프트** — `src/lib/prompts/chain/<단계>.ts`. 공통 상황 블록 재사용, 없는 사실은 `[확인 필요: ○○]`
4. **단계 정의** — `src/lib/chain/<단계>.ts`: 입력 타입 · 스키마 · 프롬프트 이름 · 앞 단계
5. **연결** — 체인 순서 목록에 한 줄. 건너뛰기 없음
6. **실행 확인** — bridge를 통해 실제 아이디어 하나로 생성, 스키마 통과 확인
7. **검증** — `npm run lint && npm run typecheck && npm run build`
8. `hatch-reviewer` → PR

## 하지 말 것
- 단계 파일에 프롬프트 문장
- bridge를 거치지 않는 직접 호출
